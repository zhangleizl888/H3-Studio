# H3 Studio workflow bundle (`work/`)

[简体中文](README.md) · English

`work/` holds the **workflow deliverables** for H3 Studio: the 7 ComfyUI graphs the product
actually uses, exported from the live workflow library together with their metadata, so a fresh
machine or a reinstall can restore them as-is.

ComfyUI itself, custom node packs, and model weights are **not** here — this repository ships no
ComfyUI copy. `work/` contains graph JSON plus the manifest only.

## Layout

```
work/
├── manifest.json                 # per-workflow metadata + required weights + required custom nodes
├── import_workflows.py           # bulk importer (standard library only, no extra packages)
├── export_from_library.py        # the reverse direction: re-export library entries into this bundle
├── workflows/                    # 7 entries × (api graph + canvas graph)
│   ├── h3-firstlast-fast.api.json      / .ui.json
│   ├── h3-motion-ref-omni.api.json     / .ui.json
│   ├── h3-drama-omni-ref.api.json      / .ui.json
│   ├── h3-omni-ref-60s-stitch.api.json / .ui.json
│   ├── voice-clone-qwen3-tts.api.json  / .ui.json
│   ├── klein-character-sheet.api.json  / .ui.json
│   └── klein-instruct-edit.api.json    / .ui.json
```

`*.api.json` is the **directly executable** graph (author-private nodes already replaced by their
ComfyUI core equivalents, weight filenames aligned to the export machine). `*.ui.json` is the canvas
form used by the library editor. Passing both to the import wizard avoids a lossy UI↔API round trip.
The author's original export and the per-node rewrite log are not in the bundle — they live in the
`workflows.graph_original` / `workflows.adaptations` database columns.

## The 7 bundled workflows

| slug | Name | Kind | Priority | Nodes/slots | Verified at export |
|---|---|---|---:|---:|---|
| `h3-firstlast-fast` | MiniMax H3 image+text → video (fast) — 图文一键生视频（加速版） | video | 120 | 20 / 30 | yes |
| `h3-motion-ref-omni` | MiniMax H3 motion transfer, omni-reference — 动作迁移·全能参考 | video | 110 | 21 / 31 | yes |
| `h3-drama-omni-ref` | Dual-model short-drama assistant — 双模双采短剧助手·全能参考生成视频 | video | 100 | 41 / 59 | no |
| `h3-omni-ref-60s-stitch` | MiniMax H3 60 s multi-asset stitch — 全能参考 60 秒·多素材拼接 | video | 90 | 58 / 101 | no |
| `voice-clone-qwen3-tts` | Voice clone 2-in-1 (IndexTTS2 + Qwen3-TTS) — 声音克隆二合一 | audio | 120 | 6 / 26 | yes |
| `klein-character-sheet` | Klein character sheet + outfit breakdown — 一键人物设定图 + 服装拆解 | image | 120 | 22 / 26 | yes |
| `klein-instruct-edit` | Klein instruct edit (FLUX) — 指令编辑 | image | 110 | 23 / 23 | yes |

Priority decides which eligible workflow auto-selection picks first for a given task kind: lighter and
more specific ones go first, the heavy 60-second multi-asset stitch is left for manual choice
(you can also turn off its `autoSelect` flag in the library).

## Three built-in workflows are intentionally not in the bundle

They are generated by backend code at runtime (`apps/api/app/gen/builtin_graphs.py`, `templates.py`):

| id | Name | Notes |
|---|---|---|
| `builtin:qwen_image` | Qwen-Image text → image | Same node does character-consistent editing when a reference image is supplied |
| `builtin:h3_video` | MiniMax H3 text/first/last frame → video | t2v / i2v / fl2v in one template; the per-shot path in the director stage |
| `builtin:h3_chain` | MiniMax H3 seamless long-take chaining | Requires custom node `H3SeamlessChainSampler` (ComfyUI-minimaxH3-SequenceForge) |

The built-ins do **not** hardcode weight names: they resolve them from the instance's `/object_info`
using normalized fuzzy matching (e.g. prefer `qwenimage21int8convrot`, fall back to `…bf16`). The 7
bundled graphs go through the import wizard's weight alignment, which **never approximates** — the exact
filename must exist on the target instance, otherwise the import reports it as missing instead of
silently substituting a look-alike.

## Import procedure

Prerequisites: the backend is running (`http://127.0.0.1:8788` by default) and **at least one online
generation instance** — the wizard needs its `/object_info` to validate nodes, align weight names and
compute gaps.

```bash
# 1) show the plan, touch nothing
python work/import_workflows.py --dry-run

# 2) import everything (entries with the same name are skipped by default)
python work/import_workflows.py --username admin --password 12345

# other useful switches
python work/import_workflows.py --token h3_xxx --only h3-     # agent token, H3 entries only
python work/import_workflows.py --instance 597 --replace      # pin an instance; delete-then-add on name clash
python work/import_workflows.py --fresh                       # drop every non-builtin entry first
```

Single-entry import via the CLI works too:

```bash
h3 workflow import work/workflows/klein-instruct-edit.api.json \
  --ui-file work/workflows/klein-instruct-edit.ui.json \
  --name "Klein 指令编辑（FLUX）" --tags "导入,图片,指令编辑" --priority 110
```

Or in the UI: **Workflows → import**, dropping `.api.json` and `.ui.json` in together.

Read each import report: a non-empty `gaps` list means the machine cannot run it yet, `adaptations`
lists the local equivalent rewrites, and `warnings` usually carry weight-name alignment notes.

### ComfyUI version

These graphs use core nodes such as `MiniMaxH3*`, `EasyCache`, `ComfyMathExpression`, `QwenImage21Cache`,
`EmptyFlux2LatentImage`, `Flux2Scheduler`, `SaveAudioMP3`, `TrimAudioDuration`, all present on
**ComfyUI 0.37.4, the verified baseline for this project**. On an older build the import health check
reports unknown nodes instead of failing halfway through a run.

## Verify and re-import

Importing is not the same as running. Trigger **Workflows → test run** per entry (it really occupies VRAM);
`verifiedAt` is only written after a successful run. After upgrading ComfyUI or installing a node pack,
rescan: `h3 workflow rescan <id>` recomputes slots and gaps against the new `/object_info`.

The bundle is self-maintaining — two scripts ship with it:

```bash
# metadata or graphs changed in the library → re-export (keep the existing filenames)
python work/export_from_library.py --keep-slugs --comfyui <path to a ComfyUI source checkout>

# new machine / fresh install → import back in
python work/import_workflows.py --username admin --password 12345
```

Pass `--comfyui` with a ComfyUI source tree to populate `customNodes` (any class type not found in
`comfy_extras` / `nodes*.py` / `comfy_api` counts as third-party); without it the field stays empty while
every class name is still recorded under `nodeClasses`. The `builtinWorkflows` and `prerequisites`
sections are maintained by hand and are preserved across re-exports.
